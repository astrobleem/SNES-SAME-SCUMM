# First Compiler Milestone: Source-Bound Room Executable Bundle

## Decision

Build one generic SCUMM v5 room-executable compile pass. Given a source room,
its ENCD/EXCD/LSCR scripts and object verb directory, it constructs a small
`RoomIR`/`ScriptIR` closure, validates control flow and direct executable
dependencies, then emits the existing cooked-room/backend artifact and source
map consumed by the current runtime.

This seam has more leverage than an isolated opcode translator: the observed
integration work repeatedly depends on complete authentic room/object/local
executable closure and correct generated selector maps. It makes source
identity and dependency analysis compiler-owned without replacing the
interpreter or runtime ABI.

## End-to-end slice

| Stage | Contract |
|---|---|
| Source | External SCUMM v5 archive + thin edition profile; one room and reachable executable sources. FATE input: the source-authenticated room-7 object-verb/local-script chain already observed. No game bytes enter the repository. |
| Synthetic source | Copyright-free minimal room/container with an object verb that starts/chains a local script and a conditional branch; same parser/compiler API. |
| Front end | Reuse resource and room/object decoders; emit typed room/verb/script identities with archive member, chunk/range, digest and original PC. |
| IR | `RoomIR`, `ObjectIR`/`VerbEntry`, `ScriptIR`, source map and explicit unknown-op nodes; preserve original encoded bytes for the current VM. |
| Analysis | Check instruction boundaries/branch targets; resolve literal `startScript`, `chainScript`, `startObject`, entry/exit/local and room edges; mark dynamic/unknown edges possible; fail if a definite body is absent. |
| Backend | Reuse `encode_cooked_room` and `generate_snes_cooked_rooms.py`; emit current SC5C plus stable selector/room-local/object-verb tables and deterministic dependency/source-map manifest. No ABI change. |
| Runtime | Existing M23A lookup and VM dispatch execute the compiled artifact. The test ROM must link the artifact generated by this path, not a validator substitute. |

The FATE identities are test inputs, never compiler special cases. A profile
names the external source edition, not “when object 119 runs, use PC X.”

## Replaces or narrows

- Manual `--rooms`, `--global-scripts`, append-local and append-object closure
  becomes analyzed output for this proven slice; explicit diagnostic roots stay.
- Stable executable selectors remain, generated from typed source identities
  and backend layout.
- Existing SC5C/current runtime interface remains initially; its producer
  boundary changes, not its semantics.

## Acceptance

1. Synthetic tests assert IR identities/source spans, control flow and graph
   edges; malformed operands/branches, missing direct bodies and duplicate
   identities fail.
2. Optional FATE integration checks authentic bytes, offsets/hashes, verb
   entries and closure against the current cooker.
3. Output manifests bind source/profile/backend identities; selector map is
   stable and cooked payloads are preserved.
4. A bounded native ROM using the emitted artifact exercises the same
   object-verb → local-script behavior. A tiny synthetic fixture uses the same
   compiler path without original data.
5. Clean tests/validation, generated-source checks, Poppy lint, assembly and
   ROM audit pass; optional archive tests honestly skip without data and fail
   if an explicitly requested archive is invalid.

This does not require whole-game symbolic execution, all-opcode IR, direct
native code generation, a new SNES interpreter or a complete gameplay route.
